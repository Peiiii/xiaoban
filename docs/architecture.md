# 架构与播放策略

本地模式：浏览器 AudioWorklet 采集 16kHz PCM → 同源 WebSocket → Node 桥接 → 千问实时 API。回复包含文字和 24kHz PCM，浏览器用设备采样率的 AudioContext 排程播放。Key 由 server/config.mjs 从明确的环境变量读取。

- `public/app.js`：通话、UI、历史与模式切换。
- `public/audio.js`：输入资源、输出队列、打断、停止和音频上下文清理。
- `public/mic-worklet.js`：采样和 PCM 分片。
- `server/realtime.mjs`：上游会话配置、事件转换、旧回复丢弃和连接清理。
- `server/index.mjs`：静态 HTTP、文字 SSE 与 WebSocket 入口。
- `public/gateway.js`：可选 GemiGo 平台登录及代理入口；未配置平台标识时使用本地服务。

流畅优先模式收到整段语音完成事件后再排程播放。它用等待完整回复换取开始播放后的连续性。低延迟模式先缓冲约 600ms；遇到欠载后增加缓冲，最高约 1800ms。缓冲无法消除上游生成等待、断网或无响应。

两种模式都在新的回复开始时记录播放策略快照。打断、关闭扬声器和挂断清空已排程及待播放音频；挂断释放麦克风轨道和音频上下文。自动语音打断依赖上游 VAD，现实设备的回声仍可能导致误触发。

文字聊天使用独立的 OpenAI 兼容 `chat/completions` SSE 服务；它不复用语音会话，也不自动朗读。三种对话模式是系统提示词，不是三个独立模型。

Node 测试覆盖协议与资源生命周期。浏览器离线渲染用于检查音频排程的空白；合成输入及节点波形只能证明工程链路，不代表真人听感或所有设备的回声表现。
